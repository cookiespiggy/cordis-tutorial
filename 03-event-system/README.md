# 第 03 课：事件系统

## 本课目标

Cordis 内置一个强大的事件总线，支持 5 种分发模式：

| 方法 | 语义 | 典型用途 |
| --- | --- | --- |
| `emit` | 同步广播，不关心返回值 | 通知类事件 |
| `parallel` | 并发执行（支持 async），等待全部完成 | 并行副作用（日志、上报） |
| `serial` | 串行执行，可短路 | 中间件链、鉴权拦截 |
| `bail` | 取第一个有效返回值 | 提供默认值 / 提前响应 |
| `waterfall` | 洋葱/中间件模型：监听器 `(payload, next)`，通过共享对象传递数据 | 数据加工流水线、洋葱模型 |
| `once` | 只触发一次 | 一次性初始化 |

## 运行

```bash
npm install
npm start
```

预期输出（顺序可能因 parallel 的 10ms 延迟略有不同）：

```
[broadcast] hello
[tick] once 监听器只执行这一次
[parallel] 任务 1 完成
[parallel] 任务 2 完成
[serial] 处理 1
[serial] 处理 1 （这一条在短路后不会执行）
[serial] n=1 结果 = undefined
[serial] 处理 2
[serial] 处理 2 （这一条在短路后不会执行）
[serial] n=2 结果 = 在 n=2 处短路
[bail] 结果 = 第一个有效结果
[waterfall] 5 -> 12 (即 (5+1)*2 = 12)
```

> 注意：`waterfall` 在本版本中是**中间件（洋葱）模型**——监听器签名为 `(payload, next)`，通过**共享的可变对象**在监听器间传递数据，必须调用 `next()` 才会继续下一个监听器。它不像 `serial` 那样把「返回值」作为下一段输入。

## 要点

- **监听器随上下文生命周期自动清理**：插件卸载时，其 `on` 注册的监听器会被一并移除，不会泄漏。
- **短路规则**：`serial` / `bail` 把「非 null、非 false、非 undefined」的返回值视为有效，立即终止后续执行。
- **事件默认全局可见**：在任意子上下文 `emit`，挂载在其它上下文的监听器也能收到（除非显式传入带过滤器的上下文）。
